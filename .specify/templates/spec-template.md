### Functional Requirements

- **FR-001**: System MUST [specific capability, e.g., "accept limit orders"]
- **FR-002**: System MUST [specific capability, e.g., "match by price-time priority"]
- **FR-003**: Users MUST be able to [key interaction, e.g., "cancel a resting order"]
- **FR-004**: System MUST [data requirement, e.g., "keep the book in memory only"]
- **FR-005**: System MUST [behavior, e.g., "emit a structured trade event on match"]

*Constitution-aligned requirements (include when the feature touches these areas):*

- **FR-C01**: Matching for a symbol MUST use a single owner goroutine with
  channel ingress only (no book-level locks).
- **FR-C02**: Matching behavior MUST be covered by deterministic replay tests
  with byte-identical trade output.
- **FR-C03**: Performance numbers MUST come from `go test -bench` reporting
  orders/sec and p50/p99 — or the feature MUST NOT claim them.
- **FR-C04**: Scope MUST stay within the active feature spec; persistence,
  multi-node, and exchange protocols are out of scope unless constitutionally
  amended.
- **FR-C05**: Strategy/market-maker logic (if any) MUST NOT be described as
  profitable or production-ready trading in code, docs, or demos.
- **FR-C06**: Trade matches and book-state changes MUST emit structured events
  on a channel, independent of whether a consumer exists yet.
